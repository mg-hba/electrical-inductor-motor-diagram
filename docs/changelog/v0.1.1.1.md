# Version 0.1.1.1 — Full Icon System

**Release Date:** 2026-10-16

## Summary

Complete icon system: every button in the application now shows a PNG
icon from `assets/icons/`, with automatic text fallback if the icon is
missing. A new `IconTextButton` component renders icon + text side by
side and makes the **entire row clickable**.

## New Components

### Icon System
- `get_icon_path()` searches all subfolders under `assets/icons/`:
  `main`, `menu`, `zoom`, `connection`, `conflict`, `app_info`,
  `docs`, `setup`, `file_ops`, `common`, `misc`
- Falls back to `assets/icons/<name>.png` if not found in subfolders
- `IconButton` (image only) and `IconTextButton` (icon + text)
- `IconTextButton` uses `ButtonBehavior` on the whole row, so clicking
  the icon **or** the text triggers the same callback

### Notifications (with icons)
- `NotificationPopup` shows an icon in the header and a larger icon
  next to the message body
- Icons by type:
  - Info → `info`
  - Success → `ok`
  - Warning → `info`
  - Error → `cancel`
  - Confirm → `info`

### Main Menu

## Technical Notes

- `assets/icons/` now contains 11 subfolders; `get_icon_path` searches
  each one before falling back to the root
- `IconTextButton` inherits `ButtonBehavior` on the full `BoxLayout`
  row, so the whole area is tappable
- Notifications use the same icon files as other buttons
- No icon file was added or removed; only the lookup and usage changed

## Known Notes

- If an icon file is missing, the button falls back to text
- Icon names must match file names exactly (`<name>.png`)
